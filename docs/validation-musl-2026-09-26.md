# Проверка базовой системы на musl — 2026-09-26

Среда: WSL2, Ubuntu 26.04.1, QEMU x86_64 TCG. Проверка выполнена в
Linux-копии проекта пользователем `neko`. Исходники musl 1.2.6 и BusyBox
1.37.0 взяты из закреплённых архивов; TinyCC — версии 0.9.27.

`bash os build` сначала установил musl и Linux UAPI в изолированный каталог
`build/toolchain-root/`, затем собрал BusyBox и TinyCC через host GCC со
спецификацией, направляющей его на эту musl. Оба итоговых файла являются
статическими ELF без интерпретатора; в TinyCC найдены символы запуска musl.
Новый initramfs прошёл проверку структуры (1408 записей).

После пересборки прошли гостевые проверки:

1. `bash os test --no-build` — консоль, компиляция и запуск C-программы,
   штатное выключение: `BOOT_TEST_PASSED`.
2. `bash os test --disk --no-build` — сохранение файлов и программы в
   `/usr/local/bin` между двумя запусками: `DISK_TEST_PASSED`.
3. `bash os test --net --no-build` — DHCP, перезапуск сетевой службы и HTTP
   внутри тестовой сети QEMU: `NETWORK_TEST_PASSED`.
4. `bash os iso` и `bash os test --iso --no-build --timeout 120` — загрузка
   через BIOS/GRUB с сохранением данных: `ISO_BOOT_TEST_PASSED`.

Существующий виртуальный диск `out/disks/state.img` не пересоздавался.
Статическую сборку гостевой C-программы командой `cc -static` после этого
изменения отдельно не проверяли; для пользовательских программ поддерживается
проверенный обычный путь `cc file.c -o file`.
