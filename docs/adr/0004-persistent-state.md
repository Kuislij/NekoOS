# ADR-004: отдельный диск для изменяемых данных

Статус: принято для первой части этапа 4. Дата: 2026-09-25.

Контекст: initramfs позволяет быстро пересобирать и проверять систему, но
любые созданные в госте файлы исчезали после выключения. Для дальнейшей
разработки нужны сохраняемые домашние папки и место для данных будущего
менеджера пакетов. Установка на физический диск пока не входит в проект.

Решение: `bash os run` создаёт при необходимости разреженный файл
`out/disks/state.img` размером 512 МиБ с ext4. QEMU подключает его через
virtio-blk. `/init` монтирует диск в `/state`, создаёт там каталоги `root`,
`home`, `var-lib` и делает bind mount на `/root`, `/home`, `/var/lib`.
Расширение этого решения добавляет каталог `usr-local` на том же диске и
bind mount на `/usr/local`; ранее сохранённые данные не перемещаются и не
удаляются. `/usr/local/bin` входит в PATH гостевой shell.
Загрузочный образ и система в `/usr` остаются в initramfs. При отсутствии
обязательного диска `/init` сообщает ошибку и не открывает shell, чтобы
запись в RAM не выдавала себя за постоянную.

Для временной проверки `bash os run --ram` не подключает диск. Команда
`bash os image` создаёт диск заранее и оставляет существующий файл без
изменений. Сборка и Git не трогают `out/disks/state.img`. Автоматический
`bash os test --disk` записывает случайный маркер, выключает VM, запускает
её вновь, проверяет маркер и удаляет только свой тестовый файл.

Следствия: пользовательские файлы живут между обновлениями initramfs, но
изменения в `/etc`, основной части `/usr`, `/var/log` пока не сохраняются.
Диск не шифруется; для резервной копии выключенной VM нужно копировать весь
файл образа.
Замена initramfs или схемы каталогов потребует отдельной миграции данных.
Это ещё не установленная на компьютер ОС и не постоянный rootfs.

См. [документацию QEMU по образам дисков](https://www.qemu.org/docs/master/system/images)
и [параметрам запуска](https://www.qemu.org/docs/master/system/invocation.html).
