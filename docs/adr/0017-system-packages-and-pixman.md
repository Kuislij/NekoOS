# ADR-017: системные пакеты и первая библиотека графического стека

Статус: принято, формат и первый пакет реализованы и проверены. Дата: 2026-09-27.
Продолжает [ADR-016](0016-real-desktop-distribution-strategy.md).

## Причина

Для Xorg, Xfce и Thunar нужны общие библиотеки, исполняемые файлы, заголовки,
шрифты и ресурсы в системном `/usr`. Гостевой NekoPkg/3 предназначен для
локальных программ в `/usr/local`: он не собирает базовую систему и не решает
эту задачу. При обычной загрузке `/usr` приходит из initramfs, а при загрузке
с системного диска — из `system.img`. Каталог `/usr/local` в обоих случаях
закрывается сохраняемым `state.img`.

## Решение

Системные компоненты собираются из закреплённых исходников против musl NekoOS
и включаются в образ **во время сборки**. Для этого используется отдельный
формат `NSPKG/1`. Он не заменяет гостевую команду `neko-pkg` и не предполагает
установки пакетов в работающей гостевой системе.

Архив `NSPKG/1` содержит канонический `manifest.json` и дерево `payload/usr`.
Манифест записывает имя, версию, архитектуру, лицензию, SHA-256 исходного
архива, заявленные зависимости, пути и SHA-256 обычных файлов. Поддерживаются
каталоги, обычные файлы и относительные символические ссылки внутри `/usr`.
Сборка фиксирует порядок файлов, владельца и время; перед включением проверяет
состав архива, суммы, пути и отсутствие конфликтов с базовым образом или
другими пакетами. Установочные скрипты из архива не выполняются. Копия
манифеста в образе остаётся в `/usr/share/nekoos/system-packages/` для учёта
происхождения файлов. При сборке проверяются архитектура, наличие зависимостей
и их минимальные версии: провайдером может быть уже установленный пакет или
другой пакет того же набора. Циклы зависимостей отклоняются. Автоматического
поиска и скачивания пакетов нет.

Первый пакет — **Pixman 0.46.4**, библиотека компоновки пикселей для будущего
X-сервера и Cairo. Рецепт [recipes/pixman](../../recipes/pixman/README.md)
фиксирует официальный исходный архив и его контрольные суммы, собирает
разделяемую `libpixman-1.so.0` против musl, сохраняет заголовки,
`pkg-config`-описание и файл лицензии. Meson 1.10.1 также закреплён как
инструмент сборочной машины; он не входит в гостевую систему. Наличие Pixman
**не означает**, что Xorg, Xfce или Thunar уже установлены и могут запускаться.
Текущий экран `neko-desktop` остаётся отдельным framebuffer-прототипом.

Для уже созданного `system.img` новая сборка сама по себе не меняет `/usr`:
обновление возможно только при выключенной VM через `bash os system-update`.
Оно проверяет кандидат на временном диске и сохраняет резервную копию перед
переключением; `state.img` с пользовательскими файлами не участвует. Состав
системных пакетов пока обновляется наложением новых файлов. Удаление файлов,
исчезнувших из новой версии пакета, и установка пакетов из работающей системы
остаются отдельной работой.

## Следующие ступени

1. **Сделано.** Pixman и динамический загрузчик musl проверены в QEMU:
   программа, связанная с `libpixman-1.so.0`, исполняется из initramfs и
   обновлённого временного системного диска. Проверки используют временные
   диски, без пользовательского `state.img`.
2. Развивать системные рецепты и зависимости для Xorg: протоколы X,
   библиотеки клиента и сервера, DRM/ввод и драйверы для виртуальных устройств
   QEMU. По мере роста измерить и увеличить лимит initramfs, размер системного
   диска и память графического профиля.
3. Собрать Xorg и проверить отдельный графический процесс и ввод в QEMU.
   Затем добавить шрифты, D-Bus, библиотеки GTK/Cairo и компоненты Xfce;
   Thunar должен запускаться самостоятельным процессом из рабочего стола.
4. Проверить создание файла в Thunar и его сохранение после перезагрузки,
   остановку сеанса и откат системного образа. Только после этого считать
   настоящий рабочий стол достигнутым.

Компоненты и их лицензии берутся из upstream-проектов. Рецепты других
дистрибутивов служат справочником для зависимостей и параметров сборки;
бинарные пакеты разных дистрибутивов не смешиваются с NekoOS.

Следующий слой X11 и проверка его работы описаны в
[ADR-018](0018-x11-client-foundation.md).
