# ADR-010: отдельный записываемый системный корень

Статус: принято для экспериментального режима `--system`. Дата: 2026-09-26.

Контекст: при обычной загрузке initramfs содержит всю базовую систему, поэтому
изменения `/etc` и основной части `/usr` исчезают после выключения. Уже есть
постоянный `state.img` для пользовательских файлов. Ему нельзя подменять
содержимое или менять порядок устройств в существующем режиме.

Решение: сборка из одного и того же дерева `build/rootfs` создаёт полный
initramfs, маленький `bootstrap.cpio.gz` и заготовку ext4
`out/images/system-template.img`. Встроенный BusyBox содержит `switch_root`.
Команда `bash os system-image` один раз копирует заготовку в сохраняемый
`out/disks/system.img` размером 256 МиБ. Если файл уже есть, команда
проверяет его тип и метку и не заменяет. Сборка также никогда не заменяет
`system.img`.

В `bash os run --system` QEMU подключает системный диск первым (`/dev/vda`),
а прежний диск данных вторым (`/dev/vdb`). Первый `/init` из bootstrap
монтирует `/dev/vda`, проверяет наличие основных файлов, переносит proc/sys/dev
и выполняет `switch_root`. Второй `/init` с системного диска монтирует
`/dev/vdb` в `/state` и привязывает постоянные `/root`, `/home`, `/var/lib`,
`/usr/local` как прежде. Записываемые `/etc` и базовый `/usr` остаются на
`system.img`; `/tmp` и `/run` остаются временными, а `/var/tmp` находится на
системном диске. Обычная загрузка, `--ram` и исходный BIOS ISO продолжают
использовать полный initramfs. Отдельный `NekoOS-system.iso` выбирает второй
пункт GRUB с bootstrap и подключает оба виртуальных диска.

Тест `bash os test --system` создаёт два временных диска, дважды загружает
гостя и проверяет сохранение системного файла в `/etc`, пользовательского файла
в `/root` и работу компилятора с системного диска. Он не подключает рабочие
`system.img` или `state.img`.

Ограничение: это ещё не обновляемая установка. Новая сборка даёт новую
заготовку, но уже созданный системный диск остаётся прежней версией.
Автоматический перенос изменений и откат будут отдельным решением. Режим
запускается напрямую через QEMU или через BIOS ISO; UEFI и установка на
физический диск пока не реализованы.
