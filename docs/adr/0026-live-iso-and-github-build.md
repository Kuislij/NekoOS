# ADR-026: отдельный Live ISO и сборка на GitHub

- Дата: 2026-10-01
- Статус: принято, реализовано
- Продолжает: ADR-024 и ADR-025

## Задача

Дать пробную загрузку NekoOS с USB без установки и перенести тяжёлую
сборку на GitHub. Постоянная VM с пользовательскими файлами сохраняется
отдельно; Live-сеанс не использует её диск.

## Решение

Профиль `live/` накладывается на общий desktop-overlay `arch/airootfs`.
Сборщик проверяет официальный bootstrap, создаёт временный Arch-chroot,
устанавливает archiso **90-1** из snapshot **2026/09/29** и вызывает mkarchiso.
Используются upstream BIOS/UEFI-шаблоны baseline и initramfs-настройки
releng, с сохранением атрибуции и GPL-текста. Общие настройки Xfce остаются
одними для GPT-диска и ISO.

Live-корень — SquashFS/overlay в RAM. Поддержаны BIOS CD, UEFI CD,
BIOS USB и UEFI USB; ISO в QEMU доступен только чтению. Внутренние диски
не монтируются автоматически, systemd GPT auto-generator отключён,
udisks/polkit ограничивают обычное GUI-монтирование внутренних устройств.
SSHD маскирован. Нет установки, постоянного overlay и Secure Boot.
Пароль `neko` и автоматический вход допустимы только для демонстрационного
образа; это не политика будущей установки.

Общий build-lock исключает гонки кэша и публикации с дисковым сборщиком
и VM. Новые артефакты публикуются после успешной сборки с SHA-256;
ранний отказ сохраняет предыдущий ISO. Контрольные суммы не являются
релизной подписью и не доказывают побайтовую воспроизводимость.

GitHub Source checks запускаются при push/PR. ISO workflow запускается
вручную, на стандартном Ubuntu runner, без секретов и права публикации.
Actions закреплены полными SHA. После unit-тестов и четырёх загрузок
QEMU выгружаются ISO, манифест и диагностика на 7 дней. Release-публикация,
подпись выпуска и комплект соответствующих исходников — отдельный этап.

## Проверка и последствия

Тест использует один сгенерированный записываемый ext4-диск: SHA-256
должен совпасть после всех четырёх загрузок. Проверяются реальные окна
и ввод, HTTPS, GCC и исчезновение файлов RAM-overlay между сеансами.
Первый запуск GitHub требуется подтвердить отдельно от локальных тестов.
Результаты фиксируются в `docs/validation-live-iso-2026-10-01.md`.

QEMU проверяет интеграцию, а физическое оборудование проверяется позже.
После Live ISO приоритет — обновления с восстановлением и собственный
центр приложений. Постоянные диски NekoOS остаются существующим способом
сохранения файлов между запусками.
