# ADR-009: сохраняемый автозапуск служб

Статус: принято для базовой системы. Дата: 2026-09-26.

Контекст: скрипты встроенных служб находятся в initramfs, который при каждом
запуске создаётся заново. Виртуальный диск уже сохраняет `/usr/local` и
`/var/lib`, поэтому его можно использовать для собственных служб и настроек
автозапуска без изменения системного образа.

Решение: `/etc/neko/boot-services` сохраняет порядок встроенных служб.
Исполняемые локальные скрипты находятся в `/usr/local/etc/neko/services` и
запускаются после встроенных в порядке имён. Имена ограничены строчными
латинскими буквами, цифрами, `_` и `-`, начинаются с буквы и содержат не более
64 символов. Совпадение с именем встроенной службы не разрешено. Ссылки вместо
скриптов не принимаются. Скрипт принимает `start`, `stop` и `status`.

Встроенная служба по умолчанию включена: `disable` создаёт отметку в
`/var/lib/neko-services/disabled`. Локальная служба по умолчанию выключена:
`enable` создаёт отметку в `/var/lib/neko-services/enabled`. Команда `list`
перечисляет имена; `list --all` добавляет состояние автозапуска и тип.
`is-enabled` возвращает состояние и код выхода. Изменение настроек возможно
только при смонтированном виртуальном ext4-диске. `start`, `stop`, `restart`
действуют сразу, но не меняют настройку следующей загрузки. `disable` удаляет
отметку и после удаления локального скрипта, чтобы при повторном создании
скрипт не включился неожиданно.

`/init` поднимает loopback независимо от сетевой службы. При неудаче запуска
службы `neko-service boot` сообщает `SERVICE_FAILED:имя`, отмечает сбой в
`/run/neko/services` и продолжает загрузку. `status` показывает ошибку в
текущем сеансе. Это оставляет консоль доступной для исправления сбойного
скрипта. Ошибки обязательного монтирования диска и базовой инициализации
по-прежнему останавливают загрузку.

Следующий шаг: отделить долгоживущие процессы от одноразовых start-скриптов,
наблюдать их состояние и определить безопасное завершение/перезапуск.
Скрипты пока выполняются от root без изоляции; постоянный системный rootfs
и пакетные службы будут отдельными решениями.
