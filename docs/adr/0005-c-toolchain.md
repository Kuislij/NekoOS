# ADR-005: начальный C toolchain внутри гостя

Статус: принято для этапа 4. Дата: 2026-09-25.

Контекст: BusyBox даёт shell и базовые команды, но внутри NekoOS нельзя было
собрать даже небольшую программу на C. Для разработки base system нужен
компилятор, C-заголовки и библиотека. Полное self-hosting и GCC пока рано:
сборка и установка крупного toolchain усложнили бы небольшой initramfs.

Варианты: перенести host GCC/glibc с их зависимостями; собрать отдельный
полный GCC toolchain; либо начать с TinyCC и musl. Первый путь привязал бы
гостя к Ubuntu. Второй пригодится позже, но сейчас дорог по размеру и
времени сборки. Выбран третий вариант.

Решение: TinyCC 0.9.27 устанавливается в `/usr/bin/tcc`, `cc` указывает на
него. musl 1.2.6 предоставляет `/usr/include`, `/usr/lib/libc.so`,
`libc.a`, стартовые объекты и загрузчик динамических программ. Заголовки
Linux UAPI создаются из того же закреплённого дерева ядра. Пути поиска
TinyCC настроены на гостевой `/usr`, чтобы программы внутри NekoOS
использовали musl.

Дополнение от 2026-09-26: musl и Linux UAPI сначала устанавливаются в
`build/toolchain-root/`. Host GCC использует сгенерированный на основе
`musl-gcc.specs` файл и собирает BusyBox и TinyCC как статические бинарники
с musl. Это начальный компилятор сборочной машины; его glibc больше не
попадает в базовые гостевые программы.

SHA256 закреплены для обоих новых архивов. Выпуск musl также проверяется
подписью с закреплённым ключом. Сборка и установка идут в изолированный
каталог проекта; host-системные каталоги не меняются. Автоматический
boot-тест компилирует C-файл внутри QEMU и запускает полученную программу.

Следствия: можно писать и собирать небольшие C-программы в `/root`, в том
числе с обычными заголовками libc. TinyCC не заменяет весь GCC/Clang,
не добавляет C++, Make, пакетный менеджер или полный набор dev-библиотек.
Проверка показала, что динамическая сборка работает, а программа от TinyCC
0.9.27 с `-static` аварийно завершается при запуске в QEMU. Статическую
сборку не заявляем как рабочую. Смешение glibc и musl в базовых бинарниках
устранено дополнением от 2026-09-26. Путь к более полному toolchain остаётся
открытым.

Источники: [документация TinyCC](https://bellard.org/tcc/tcc-doc.html),
[объявление musl 1.2.6](https://www.openwall.com/lists/musl/2026/03/20/1).
