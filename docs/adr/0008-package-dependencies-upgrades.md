# ADR-008: зависимости и обновление локальных пакетов

Статус: принято для продолжения этапов 5–6. Дата: 2026-09-26.

Контекст: NekoPkg/1 позволял поставить одну команду, но не выражал её
потребность в другой программе и не менял установленную версию. Существующие
архивы и команды на виртуальном диске должны продолжить работать.

Решение: NekoPkg/2 сохраняет структуру архива и девять строк манифеста.
Версия становится тройкой неотрицательных чисел `MAJOR.MINOR.PATCH`.
Поле `depends` содержит `none` или до восьми требований `имя>=версия`.
Установщик проверяет наличие, минимальную версию и SHA-256 зависимости.
Удаление запрещено, если другой установленный пакет объявил требование к
удаляемому. Зависимости устанавливаются вручную; локальный менеджер пока
не выбирает архивы и не разрешает ограничения с верхней границей.

Каждая новая версия хранится в собственном каталоге
`/usr/local/lib/neko-pkg/store/<name>@<version>`. Активный файл выбирает
ссылка `/usr/local/bin/<name>`. При `upgrade` новый каталог проверяется
и подготавливается заранее, а ссылка заменяется атомарным переименованием.
После переключения старый каталог удаляется. Если операция прервётся,
следующий вызов менеджера уберёт временную ссылку и неактивный каталог.
Старые архивы NekoPkg/1 остаются установимыми. Менеджер также распознаёт
прежний путь установленного пакета `store/<name>`, поэтому пакет 0.1.0
можно обновить без предварительного удаления.

Следствие: отказ при отсутствии зависимости или попытке удалить нужный
пакет сохраняет действующую команду. Обновление допускается только на
большую числовую версию и использует NekoPkg/2. Гарантия совместимости
интерфейса по номеру версии отсутствует; для пакетов из нескольких файлов,
автоматического получения зависимостей и отката понадобится более полная
транзакционная модель.
