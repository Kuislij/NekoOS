# ADR-011: обновление системного диска с откатом

Статус: принято для экспериментального режима `--system`. Дата: 2026-09-26.

`system.img` может содержать изменённые настройки `/etc` и дополнительные
файлы. Сборка по-прежнему никогда не заменяет его автоматически. Явная команда
`bash os system-update` требует выключенную VM и блокирует параллельный запуск.
Она проверяет хеши сборки, копирует текущий ext4-образ во временный файл и
загружает QEMU со специальным `/neko-update` из нового полного initramfs.
Гость обновляет базовые файлы на копии; диск данных пользователя к этой VM не
подключается. Затем хост проверяет ext4 и обычную загрузку обновлённой копии
с отдельным пустым диском данных. Только после успешной проверки старый образ
получает имя `system-backup-...img`, а копия атомарно становится `system.img`.
До переключения сбой не меняет рабочий диск.

Для `/etc` новая сборка содержит манифест хешей исходных настроек. Если
существующий файл совпадает с прежним исходным хешем, он обновляется. Если
отличается или прежний манифест отсутствует, местное значение сохраняется,
а новое записывается рядом как `.neko-new`, если такого файла ещё нет.
Дополнительные файлы и `/var/tmp` остаются на копии диска. Базовые файлы
`/usr` заменяются новой сборкой; `/usr/local` исключён и обычно привязан к
`state.img`. Если пользователь редактировал базовый файл `/usr`, его прежнее
содержимое остаётся доступно в резервной копии и возвращается откатом.

`bash os system-rollback ИМЯ` проверяет выбранную копию ext4, сохраняет
текущее состояние как ещё одну резервную копию и атомарно возвращает выбранную.
Команда не меняет `state.img`. Резервные копии не удаляются автоматически.
Это механизм обновления виртуального образа, а не установщик или полная
транзакционная система пакетов.
