# ADR-028: подтверждение первой загрузки и автоматический возврат в VM

Дата: 2026-10-06. Статус: принято для управляемой QEMU VM.

## Причина

Проверка кандидата перед включением уменьшает риск обновления, но после
переключения всё ещё возможен отказ загрузки или графического сеанса.
Один маркер доступности консоли не доказывает работоспособность рабочего
стола. Нужны сохранённое состояние первой попытки, подтверждение готовности
и возврат к предыдущему корню, если новая версия не подтвердилась.

## Решение

Метаданные управляемой VM переходят в формат 2. Активация атомарно выбирает
новый корень, удерживает предыдущий и записывает `trial` со стадией `armed`.
Перед запуском QEMU стадия становится `booting`; запись и родительский
каталог синхронизируются до старта гостя. Для попытки создаётся свежий nonce.

Хост использует существующую serial-консоль для проверки: обычный UID 1000,
systemd, отдельный смонтированный HOME, соответствие работающего ядра
установленному linux, активный LightDM, Xfce session/window manager,
видимые панели и фон desktop, доступный Thunar. Успешный ответ должен
содержать nonce этой попытки. Только после всей проверки `trial` очищается
атомарной записью. Интернет и GCC не требуются для подтверждения запуска;
проверки сети, компилятора и пакетов остаются частью staging.

При таймауте или ошибке готовности QEMU сначала останавливается. Хост
проверяет контрольную сумму предыдущего корня, сохраняет неудачный корень
как предыдущий, выбирает восстановленный корень и записывает `last_recovery`.
HOME не переключается и не восстанавливается из старой копии. Выполняется
одна попытка запустить восстановленный desktop; повторного автоматического
переключения между двумя неисправными корнями нет.

Если управляющий процесс завершился до подтверждения, сохранённая стадия
`booting` при следующем запуске приводит к такому же возврату.
Если QEMU осталась работать после смерти управляющего процесса, файловая
блокировка QEMU не позволяет открыть её корень и переключить состояние.
Пользователь должен штатно остановить оставшуюся VM; хост не убивает
произвольные процессы автоматически. Эта граница опирается на
[документированные блокировки образов QEMU](https://www.qemu.org/docs/master/system/images.html#disk-image-file-locking).

Закрытие окна/отмена пользователем до подтверждения и обычная ошибка
запуска QEMU на хосте возвращают состояние в `armed`, сохраняя выбор
системы для повторной попытки. Ошибка после подтверждения не запускает
откат автоматически. Пока первая загрузка не подтверждена, подготовка
следующей версии и удаление единственного fallback запрещены.

Версия 1 читается без изменения дисков. При наличии предыдущего корня
существующая VM получает проверку первой загрузки; формат 2 записывается
при первом переходе состояния. Исходные qcow2 и HOME не пересоздаются.
Обычная VM и Live ISO продолжают работать прежними путями.

## Последствия и пределы

Автоматическое восстановление относится к первому запуску выбранного
поколения через управляемый launcher. Профиль использует serial-autologin;
отключение этой консоли требует нового канала подтверждения.
Это не общий монитор всех последующих сбоев и не защита от злонамеренного
гостя: nonce различает попытки и не заменяет доверие к образу.
Гость видит актуальный HOME, поэтому изменения данных приложениями до
отказа остаются в HOME; обратная совместимость всех форматов не гарантируется.

По умолчанию первая проверка имеет таймаут 180 секунд. Переключение выполняется
на хосте при остановленных дисках; это не механизм для физических установок,
Secure Boot или BIOS/UEFI переменных на настоящем компьютере.
Подписанный каталог выпусков, stable-канал, зеркала и GUI обновлений —
отдельные следующие этапы. Метаданные, логи и диагностические снимки
сохраняются в прежней Linux-копии WSL на F:.

## Проверка

Unit-тесты покрывают миграцию, подтверждение только текущего nonce,
атомарность восстановления, запрет удаления fallback, повреждённый fallback,
закрытие окна, ошибку хоста, отсутствие повторного цикла и ошибку после
подтверждения. QEMU-тест на временных дисках проверяет отсутствующее ядро,
masked LightDM, настоящий SIGKILL управляющего процесса с оставшейся
приостановленной QEMU, отказ переключать занятый диск, последующее
восстановление и успешный запуск без сети. Пользовательские VM не подключаются.
