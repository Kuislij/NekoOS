# Оконный рабочий стол: проверка 2026-09-27

Проверка выполнена в Ubuntu WSL2 и QEMU для новой версии `neko-desktop`.
`bash os build` завершилась с `BUILD_READY`. Четырнадцать модульных тестов Python,
включая проверки моделей окон, файлов и системных сведений, прошли.

`bash os test --graphics --no-build --timeout 120` завершился с
`GRAPHICS_TEST_PASSED`. Тест загрузил гостя с virtio-GPU и устройствами ввода,
проверил службу `desktop`, пользователя `neko`, доступность экрана и устройств.
Через монитор QEMU были отправлены клавиши рабочего стола: открыть Files,
создать файл `test.txt` и подтвердить имя. Затем команда внутри гостя
подтвердила появление `/home/neko/test.txt`. Тест также проверил остановку и
повторный запуск графической службы и штатное завершение гостя. Окно QEMU на
хосте для этого автоматического теста не открывалось.

`bash os test --graphics --system --no-build --timeout 150` завершился с
`GRAPHICS_SYSTEM_TEST_PASSED`. Он повторил графический и файловый сценарий
после загрузки через отдельный системный диск. Использовались временные
системный и пользовательский диски; рабочие `out/disks/system.img` и
`out/disks/state.img` этот тест не заменял и не подключал.

Отдельно прошёл обычный загрузочный тест `bash os test --no-build` с маркером
`BOOT_TEST_PASSED`. В ручной записи экрана QEMU (1280×800) были открыты Files
и System: интерфейс показал созданный через клавиатуру `TEST.TXT`, а System —
версию ядра, процессоры, память и диск работающего гостя. Изображение сохранено
в [документации проекта](assets/windowed-desktop.png).

После этих проверок обновлён рабочий `out/disks/system.img` командой
`bash os system-update --no-build`. Команда завершилась с
`SYSTEM_UPDATE_READY` и создала резервную копию
`system-backup-20260927T084145Z-f3fe5509.img`. Контрольная сумма
`out/disks/state.img` до и после обновления совпала:
`9680b863532416902606a6e16069326098f74b534baa54a317530b7ef4d865f0`.

Проверка подтверждает запуск оболочки и создание файла через её ввод в QEMU.
Окна Files, System, About и Help пока рисует один процесс напрямую в
framebuffer. Отдельные графические приложения, Wayland, композитор и работа
на физическом компьютере этим тестом не подтверждены.
