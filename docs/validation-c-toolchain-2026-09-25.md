# Проверка C toolchain — 2026-09-25

Среда: WSL2, Ubuntu 26.04.1, QEMU 10.2.1, x86_64 TCG. Сборка выполнена
пользователем `neko` в Linux filesystem. Источники: TinyCC 0.9.27 и
musl 1.2.6 из закреплённых URL; SHA256 проверены. Подпись musl проверена
ключом `836489290BB6B70F99FFDA0556BCDB593020450F`.

Результаты:

1. `bash os build` создал initramfs с `cc`/TinyCC, заголовками musl и Linux,
   загрузчиком musl, `libc.so`, `libc.a` и стартовыми объектами.
   `tools/validate_image.py` принял архив: 1393 записи.
2. `bash os test --no-build` внутри QEMU создал C-файл с `<stdio.h>`, собрал
   его командой `cc`, запустил и получил `C_READY`. Затем собрал и запустил
   встроенный пример, получил `Hello from NekoOS` и завершился штатно:
   `BOOT_TEST_PASSED`.
3. `bash os test --disk --no-build` прошёл две загрузки с проверкой данных:
   `DISK_TEST_PASSED`.
4. В интерактивной NekoOS исходник с `<stdio.h>` и `<math.h>` был собран
   с `-lm`, вывел `math=9`, пережил выключение вместе с исполняемым файлом
   и запустился вновь. Тестовые файлы затем удалены.
5. Два теста Python harness прошли. Проверки синтаксиса shell/Python прошли.

Ограничение: `cc -static` создал исполняемый файл, но тот получил segfault
при запуске в QEMU. Поэтому статическая линковка этой комбинацией TinyCC
и musl пока не поддерживается. Обычная динамическая сборка проверена.
Это ещё не полноценный GCC/Clang toolchain и не self-hosting NekoOS.
