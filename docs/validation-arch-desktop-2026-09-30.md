# Проверка Arch-образа NekoOS — 2026-09-30

Статус: **пройдено**. Полная сборка и реальный тест QEMU завершились
с кодом 0: две BIOS-загрузки и третья UEFI с полноценным Xfce-сеансом.

## Подтверждённая сборка

Основная база — официальный Arch bootstrap 2026.09.01 и снимок
официальных репозиториев 2026/09/29. Bootstrap проверен по закреплённой
SHA-256 и OpenPGP, бинарные пакеты установлены pacman с проверкой подписей.
В `out/arch/images/packages.lock` записан **471 установленный пакет**.

Получен отдельный разреженный диск **12 ГиБ с GPT**: BIOS boot,
EFI-раздел 256 МиБ и записываемый ext4-корень. Штатное ядро Arch и
mkinitcpio включены в образ. GRUB установлен для BIOS и x86_64 UEFI;
проверка ext4 через e2fsck завершилась успешно. `boot-mode.txt`
содержит `grub`. Фактические BIOS- и UEFI-загрузки GRUB проверены в QEMU.

В `out/arch/images/` опубликованы `system-template.img`, `vmlinuz-linux`,
`initramfs-linux.img`, `packages.lock`, `snapshot.txt`, `boot-mode.txt`
и `SHA256SUMS` для этих шести файлов. Старые musl-образы, их системный
диск и диск пользовательских данных не подменялись новым Arch-шаблоном.

## Среда и статические проверки

Windows-хост, Ubuntu в WSL2, Linux-копия `/home/neko/src/NekoOS`.
Ubuntu перенесена в `F:\WSL\Ubuntu`; полная длина и SHA-256 её VHD
совпали до и после переноса. Нативный Linux-путь рабочей копии сохранился.
Большие сборки, пакетный кэш и VM-данные теперь хранятся на F:.

Итоговый прогон в WSL после исправления обычного перезапуска VM:
**57 unit-тестов прошли**, 36 прежних и 21 для Arch-инструментов.
Windows-скрипт `Start-NekoOS.ps1` прошёл проверку синтаксиса
и фактический запуск полного теста с видимым QEMU.

Доступность KVM на текущем WSL-хосте проверена: `neko` добавлен в группу
`kvm`, новый процесс получил чтение/запись `/dev/kvm`. Launcher выбирает
KVM с CPU `host`, на хостах без доступного KVM — TCG с CPU `max`.

Профиль подготовил обычный аккаунт `neko` с паролем `neko`, root-пароль
заблокирован, sudo запрашивает пароль. LightDM настроен на автоматический
вход в Xfce, Thunar — на открытие домашнего каталога. Русская локаль,
раскладки US/RU с Alt+Shift и NetworkManager входят в конфигурацию.
Файлы системного overlay принадлежат root: каталоги 755, обычные файлы 644,
sudoers 0440. Родительские каталоги пользовательской `.config` принадлежат
`neko`; их доступность записи проверена в госте. `NEKO_ARCH_READY`
подтвердил serial-вход; полный графический сеанс проверен отдельно.

Полный тест с UEFI выполнен командой:

```bash
bash os arch test --no-build --headless --uefi
```

Тест сделал две BIOS-загрузки и третью UEFI с одного отдельного временного
qcow2-диска; OVMF использовал свои временные переменные firmware.
Пользовательская VM в `out/arch/disks/system.qcow2` к тесту не подключалась.
Завершение подтверждено `ARCH_DESKTOP_TEST_PASSED` и кодом 0.

QMP передал настоящие события USB tablet: координаты X11 совпали
с ожидаемыми в пределах четырёх пикселей. События клавиатуры создали
`/home/neko/neko-gui-check` через Thunar. Затем в госте записан русский
`README.txt`; после перезагрузок проверены его владелец и SHA-256 до новых
записей. Панели проверены как видимые окна типа `DOCK`, рабочий стол —
как видимый `DESKTOP`; одного наличия процессов для успеха недостаточно.
Настоящий снимок первой загрузки просмотрен: фон NekoOS, верхняя и нижняя
панели, русский Thunar. Firefox проверен как отдельное графическое окно,
HTTPS — запросом из гостевой системы.

Дополнительный Windows-прогон `.\Start-NekoOS.ps1 -Test` также
завершился с кодом 0 и прошёл две BIOS-загрузки со всеми проверками.
Окно QEMU отображалось через WSLg; после завершения тестовые VM остановлены.

Логи находятся в `build/logs/arch-test-*.log`, снимки —
в `out/previews/arch-desktop*.png` и `arch-browser.png`; это локальные
артефакты, исключённые из Git. Копия проверенного снимка для документации —
[`docs/assets/arch-desktop.png`](assets/arch-desktop.png).

Для обычного запуска готового образа: `bash os arch run --no-build`,
из PowerShell в `F:\NekoOS` — `.\Start-NekoOS.ps1`.
Сохраняемый qcow2 зависит от `base-<SHA256>.img` и метаданных рядом с ним;
для резервной копии сохраняется весь `out/arch/disks` при выключенной VM.
Графический обычный запуск пишет подробности в `build/logs/arch-run.log`.
Он допускает штатную перезагрузку из рабочего стола; у QA-запуска
сохраняется `-no-reboot`, чтобы неожиданная перезагрузка не скрывала ошибку.
Срок одной тестовой загрузки вместе с проверками — 480 секунд по умолчанию;
`--timeout SECONDS` позволяет его изменить.

## Проверенные границы

Это рабочий Arch/Xfce-образ для VM. Live ISO, установщик, физическое
оборудование, звук и полный цикл системных обновлений ещё не проверены.
Установка подписанных пакетов и конфигурация rolling-зеркала pacman
не заменяют проверку обновления работающей системы. Перенос старых
пользовательских данных не выполнялся автоматически.
