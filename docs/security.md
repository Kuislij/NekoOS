# Границы безопасности и риски

Скрипты проекта не должны менять Windows Boot Manager, BCD, EFI-раздел,
таблицы разделов, физические диски, реальный GRUB и UEFI boot entries.
Любые будущие операции такого рода требуют отдельного явного разрешения.

QEMU-запуски подключают только файл виртуального диска из `out/disks/`;
физические диски, сеть и общие каталоги не подключаются. Bootstrap
только проверяет инструменты; `--install` явно устанавливает host-зависимости
внутри Ubuntu/Debian через apt. Это не пакетная система NekoOS.

Основные риски дальнейшей разработки:

* Состояние WSL влияет на сборку: записывать версии, позже закрепить среду.
* TCG может быть медленным: сначала измерить, затем оценивать ускорение.
* Сборки на NTFS имеют отличия прав/ссылок: собирать в Linux filesystem.
* Рецепт выполняет код: до sandbox не запускать недоверенные рецепты.
* SHA256 проверяет целостность, но не заменяет доверенный источник hashes
  и проверку upstream-подписей.
* Ошибка установки пакета повреждает rootfs: staging, журнал транзакций,
  тесты прерывания и восстановление должны предшествовать реальной установке.
* Лицензии компонентов требуют учёта исходников и условий распространения.

Текущая сборка скачивает закреплённые upstream-архивы по HTTPS и проверяет
SHA256 при каждом запуске. Linux дополнительно проверяется по подписи
Greg Kroah-Hartman с закреплённым fingerprint. В каталоге upstream BusyBox
1.37.0 опубликованы SHA256/SHA512, но не отдельная подпись этого tarball;
для него текущая проверка ограничена HTTPS и закреплённым SHA256.

Сборка запускается обычным Linux-пользователем. Fakeroot имитирует владельцев
и устройства для cpio; он **не является sandbox**. Upstream build scripts
пока имеют доступ к файлам и сети пользователя WSL. Недоверенные community
recipes запускать нельзя. Файл виртуального диска содержит пользовательские
данные в открытом виде и доступен с правами Linux-пользователя WSL.
Кэш извлечённых исходников считается локально
доверенным; подпись исходного архива не защищает от его ручного изменения.

Целевая схема: официальный upstream → проверка → sandbox без сети → пакет
→ автоматические проверки → подпись репозитория. Sandbox и пакетная
инфраструктура пока не реализованы. Root shell без пароля допустим только
в текущей изолированной VM без сети; это не модель аутентификации будущей ОС.
