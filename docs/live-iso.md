# Live ISO NekoOS

Live ISO позволяет открыть рабочий стол без установки. Профиль использует
Archiso **90-1** из закреплённого снимка **2026/09/29**, официальный Linux,
Xorg/Xfce, Thunar, Firefox, NetworkManager, Bash, GCC и firmware.
Артефакты и временные файлы отделены от обычного сохраняемого GPT-образа.

## Запуск и проверка

В PowerShell из `F:\NekoOS`:

```powershell
.\Start-NekoOS.ps1 -Iso
```

Откроется окно QEMU с автоматическим входом в Xfce. Для UEFI и виртуальной
флешки: `-Iso -Uefi -Usb`. Параметр `-Iso -Test` автоматически загружает
BIOS CD, UEFI CD, BIOS USB и UEFI USB; `-Headless` скрывает окна теста.
`-Iso -Build` пересобирает Live ISO. Без `-Iso` запускается прежний
сохраняемый системный диск; файлы из него не переносятся в Live-сеанс.

Пользователь и пароль демонстрационного сеанса — `neko`. Sudo требует
пароль; пароль root заблокирован. Русский интерфейс и раскладки US/RU,
переключение Alt+Shift. Для завершения используйте меню выключения Xfce.

**Файлы и настройки Live-сеанса временные.** Корень — SquashFS плюс
записываемый overlay в RAM, с пределом 50% доступной памяти. После выключения
изменения исчезают. Это ограничение включает установленные в сеансе пакеты.
Установщика, постоянного overlay и поддержки Secure Boot сейчас нет.
Внутренние диски автоматически не монтируются; SSH выключен.
Пользователь с sudo может вручную обращаться к дискам — Live-политика
не защищает от осознанной команды администратора.

Linux-команды из нативной Linux filesystem, от обычного пользователя:

```bash
bash os arch iso build
bash os arch iso verify
bash os arch iso test --no-build --headless
bash os arch iso run --no-build --uefi --usb
```

Хосту нужны curl, GnuPG, tar, zstd, rsync, Python, util-linux, e2fsprogs,
QEMU и OVMF. Сборщик получает Linux-root через WSL или sudo, создаёт
изолированный chroot, ставит закреплённый archiso и вызывает mkarchiso.
Archiso не требуется устанавливать на Ubuntu-хост. Общий пакетный кэш
используется с блокировкой, параллельная замена запущенного ISO запрещена.
Перед сборкой требуется минимум **12 ГиБ** свободного места.
Временное дерево удаляется; пакетный кэш сохраняется для следующих сборок.
Сборка и кэш остаются в `/home/neko/src/NekoOS` на WSL-диске **F:**.

## Получение ISO

Локальные результаты находятся в `/home/neko/src/NekoOS/out/arch/iso/`:

| Файл | Содержимое |
| --- | --- |
| `nekoos-live-x86_64.iso` | Hybrid ISO для BIOS/UEFI CD и USB |
| `packages.lock` | Фактически включённые пакеты и версии |
| `build-info.json` | Snapshot, commit, изменение исходников, хэш профиля, режим Live |
| `archiso-version.txt` | Версия сборщика из подписанного пакета |
| `boot-modes.txt` | Четыре проверяемых способа загрузки |
| `SHA256SUMS` | SHA-256 пяти артефактов |

Каталог доступен из проводника Windows:
`\\wsl.localhost\Ubuntu\home\neko\src\NekoOS\out\arch\iso`.
Можно скопировать его на F: обычным проводником.
ISO и кэш не добавляются в Git.

Облачная сборка:

1. Откройте [Build NekoOS Live ISO](https://github.com/Kuislij/NekoOS/actions/workflows/live-iso.yml).
2. Нажмите **Run workflow**, выберите `main`, запустите.
3. Дождитесь зелёного результата. Сборка выполняет unit-тесты и четыре
   настоящие загрузки QEMU; ISO выгружается только после успеха.
4. В разделе **Artifacts** скачайте `nekoos-live-x86_64-<номер>` и распакуйте.
   GitHub может потребовать вход для скачивания артефактов. Срок хранения — 7 дней.
   Отдельный артефакт содержит логи, снимки экрана и итог QEMU-тестов.

Workflow использует стандартный Ubuntu runner, запускается только вручную,
ограничен 90 минутами и не публикует Release. Actions закреплены полными
commit SHA, токен имеет только `contents: read`, ключей релизной подписи нет.
Лёгкие Source checks запускаются при push и pull request.

Проверка скачанного ISO в PowerShell:

```powershell
Get-FileHash .\nekoos-live-x86_64.iso -Algorithm SHA256
Get-Content .\SHA256SUMS
```

Сравните хэш с первой строкой манифеста. SHA-256 выявляет повреждение файла;
он не заменяет отдельную подпись выпуска. Bootstrap проверяется по SHA-256
и закреплённому OpenPGP-ключу, пакеты — по обязательным подписям pacman.

## Пробная загрузка на компьютере

Физическое оборудование пока не прошло проверки; успешные тесты QEMU
не гарантируют работу каждого GPU, Wi-Fi или звукового устройства.
Для текущего ISO нужен x86_64-компьютер с отключённым Secure Boot.
Разумная первая конфигурация — 4 ГиБ RAM или больше.

Для записи можно использовать [Rufus](https://rufus.ie/): выберите **свою
USB-флешку** по модели и объёму, выберите ISO, нажмите старт; при вопросе
ISO/DD выберите **DD**. Запись полностью стирает выбранную флешку.
Проект не выбирает носитель и не записывает физические диски автоматически.
Перезагрузитесь и выберите USB в меню загрузки компьютера. Внутренний диск
не требуется выбирать или размечать. После проверки выключите NekoOS
через меню Xfce и извлеките флешку.

Порядок записи hybrid ISO описан в
[официальной инструкции Rufus](https://github.com/pbatard/rufus/wiki/FAQ#user-content-why-doesnt-rufus-recommend-dd-mode-over-iso-mode-for-iso-hybrid-images)
и [ArchWiki](https://wiki.archlinux.org/title/USB_flash_installation_medium).
Присутствие firmware в образе не является заявлением о проверке оборудования.

## Что проверяет тест

Каждый из четырёх запусков загружает ISO через его загрузчик, без передачи
ядра из хоста. Проверяются overlay-корень, обычный пользователь, sudo,
панели и desktop Xfce, Thunar, Firefox, GCC с реальной C-программой и HTTPS.
QMP передаёт настоящие события мыши и клавиатуры; Thunar создаёт каталог.
При следующей загрузке этот каталог отсутствует — данные Live сброшены.

К VM подключается только сгенерированный ext4-файл 64 МиБ с контрольной
меткой. Он доступен записи, чтобы обнаружить нежелательную запись:
проверяется отсутствие монтирования, а после каждого выключения его
SHA-256 сравнивается с исходной. Пользовательская VM и физические диски
хоста в тест не подключаются. Подробности текущего результата —
[отчёт Live ISO](validation-live-iso-2026-10-01.md).
