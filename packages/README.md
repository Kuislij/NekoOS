# NekoPkg/1, NekoPkg/2 и NekoPkg/3

Форматы NekoPkg/1 и /2 предназначены для одной команды.
Такой пакет `.npkg` — gzip-сжатый USTAR-архив ровно из двух обычных файлов:
`manifest` и `payload`. `payload` — исполняемый файл размером от 1 байта
до 16 МиБ. Манифест содержит фиксированные строки `NEKOPKG/1` или
`NEKOPKG/2`, `name`, `version`, `arch=x86_64`, `license`, `depends`, `path`,
`size` и `sha256`.
Имя команды допускает строчные латинские буквы, цифры и дефис, начинается
с буквы. `path` всегда равен `/usr/local/bin/<name>`.

NekoPkg/1 остаётся читаемым для ранее созданных пакетов и требует
`depends=none`. Для новых пакетов `tools/make_package.py` по умолчанию
создаёт NekoPkg/2: версия строго `MAJOR.MINOR.PATCH` с числовыми частями
от 0 до 9999, а `depends` равен `none` либо списку до восьми требований
`имя>=версия` через запятую. Зависимости должны быть уже установлены;
менеджер не скачивает их автоматически. Пока доступны только минимальные
версии, без верхних границ и разрешения сложных конфликтов.

Внутри NekoOS `neko-pkg info FILE.npkg` проверяет состав архива, его типы,
размер и SHA-256 перед показом метаданных. `install` делает ту же проверку,
готовит файл в каталоге пакетов на виртуальном диске и только затем создаёт
ссылку команды в `/usr/local/bin`. `upgrade` проверяет новую версию и
зависимости, готовит её рядом со старой и атомарно переключает ссылку.
`remove` не удаляет пакет, от которого зависит другая установленная команда.
`list`, `verify` и `remove` работают с активной версией; незавершённый
временный каталог или неактивная версия убирается при следующем вызове.
Пакеты остаются локальными: нет подписей, репозиториев и скриптов установки.
Архив сам по себе не является доверенным
источником: SHA-256 обнаруживает повреждение файла относительно манифеста,
но не подтверждает автора.

Чтобы добавить свой пакет, в Linux-копии проекта создайте исполняемый файл
или shell-скрипт, затем выполните:

```bash
python3 tools/make_package.py --name mytool --version 1.0.0 \
  --license NOASSERTION --file /path/to/mytool \
  --output packages/local/mytool-1.0.0.npkg
bash os run
```

Сборка копирует архивы из `packages/local/` в
`/usr/share/nekoos/packages/` образа; эта локальная папка исключена из Git.
После появления `neko#` выполните:

```sh
neko-pkg install /usr/share/nekoos/packages/mytool-1.0.0.npkg
mytool
neko-pkg verify mytool
neko-pkg remove mytool
```

Для новой версии создайте другой исполняемый файл и архив с большей
версией, затем выполните `neko-pkg upgrade FILE.npkg`. Чтобы потребовать
установленную программу, добавьте при создании архива флаг
`--depends 'other-tool>=1.2.0'` (несколько зависимостей — несколько флагов).
Перед удалением такой зависимости сначала удалите нуждающийся в ней пакет.

Примеры `neko-greet` и `neko-companion` создаются при сборке из
`packages/examples/`. Версия `neko-greet` 0.1.0 имеет старый формат;
0.2.0 и 0.3.0 демонстрируют обновление, а `neko-companion` требует
`neko-greet>=0.2.0`.
Установка не запускает код пакета: программа выполняется только по команде
пользователя. Установка возможна лишь в VM с сохраняемым диском.

## Дополнительные файлы в NekoPkg/3

NekoPkg/3 сохраняет главное исполняемое `payload` и добавляет до 64 обычных
файлов суммарным размером до 32 МиБ. Архив перечисляет все файлы после
`manifest` и `payload` в алфавитном порядке. В манифесте после прежних девяти
строк находятся `files=N` и по строке
`file=files/share/ИМЯ|РАЗМЕР|SHA256|644` или
`file=files/lib/ИМЯ|РАЗМЕР|SHA256|755` на каждый ресурс. Ресурсы допускаются
только внутри `share/` и `lib/`; ссылки и переходы `..` запрещены. Менеджер
проверяет тип, размер и SHA-256 каждого файла до установки и при `verify`.

Для сборки примера с ресурсом:

```bash
python3 tools/make_package.py --name neko-theme --version 1.0.0 \
  --license NOASSERTION --file packages/examples/neko-theme.sh \
  --resource share/message.txt=packages/examples/neko-theme-v1.txt \
  --output packages/local/neko-theme-1.0.0.npkg
```

Флаг `--resource` кладёт неисполняемый файл, `--program` — исполняемый.
При их использовании сборщик автоматически выбирает NekoPkg/3; явный
`--format 3` тоже поддерживается. После `neko-pkg install` данные доступны по
постоянному пути `/usr/local/share/neko-theme/message.txt`, а программы из
`lib/` — под `/usr/local/lib/neko-theme/`. Публичные пути одного пакета не
могут занять уже существующие файлы или каталоги других пакетов.

Для новой версии соберите другой архив с большей версией и выполните
`neko-pkg upgrade FILE.npkg`. Ссылка `active/<name>` переключает команду,
библиотеки и данные одной операцией переименования. Первоначальная установка
и удаление создают или убирают несколько ссылок по очереди; при прерывании
менеджер очищает незавершённое состояние при следующем запуске. Старые
NekoPkg/1 и /2 по-прежнему устанавливаются, а `upgrade` позволяет перейти
с них на /3. Обратное обновление с /3 на /2 запрещено.
